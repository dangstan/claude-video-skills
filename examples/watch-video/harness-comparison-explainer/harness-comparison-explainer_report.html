What the video actually is

A single creator, filmed at his desk with a screen share, reporting a week of hands-on use of DeepSeek Harness -- an open-source agent harness released as a developer preview -- against the Claude Code and Codex setup he already runs. He is not a professional software developer and says so; his workload is research, knowledge work, document creation and video production, and the review is scoped to that. The framing device is a taxonomy: a harness is the loop, tool set, prompt scaffolding, context injection, storage and UI wrapped around a model, and the model is a part you can pull out and replace. Closed-source harnesses let you change the engine but not the chassis. This one is a box of parts, and its own landing page says so in three words: everything is a plugin.

The substance sits in three head-to-head runs with the model pinned to Claude Opus 5 on both sides. DeepSeek Harness wins the retrieval race by a wide and visible margin. It loses on depth, on caution, and on the thing he cares about most -- whether he would put the output in front of a client. The customization story, which is the harness's entire premise, is assessed from the settings screens rather than from anything built, because he deliberately installed no plugins in order to see how the thing feels out of the box. The verdict is a clean no with a named exception: it does not replace Claude Code for his work, and it very plausibly does for someone who has actually felt the wall of a fixed harness.

"Everything is a plugin" -- and one thing the narration drops

He reads the capability list off the product page. He leaves out two items, and one of them is the whole premise.

Headline Everything is a plugin under DeepSeek Harness developer preview. The sentence beneath: every capability is a plugin that can be swapped or recomposed -- models, tools, skills, sessions, sandboxes, storage, loops, scheduling, and the UI. Quick start is one line: npx @deepseek-ai/dsh web.
02:09

The scope he sets, and the supply-chain warning

No third-party plugins, none of his own: he wants the out-of-the-box feel. Then the caveat that an open plugin ecosystem is a place strangers can put code -- have Claude Code or Codex review anything you pull off the internet before it runs. Worth noticing that this choice removes the harness's headline feature from the evidence base.

Setup: a key, and the catalogue opens

He handed the GitHub link to Codex and asked it to set the project up; it runs on localhost. Settings, Models, paste an OpenRouter key, and every model on OpenRouter is selectable. There is no way to authenticate against an existing Claude or Codex subscription -- it is per-token API billing.

Model picker filtered to openrouter, DeepSeek section listing V3 0324, V3.1, R1, R1 0528, V3.1 Terminus, V3.2, V3.2 Exp, V4 Flash. Composer chips: workspace Herk-2, Standard mode, Workspace Write, Claude Opus 5 Default.
04:08

Four modes, chosen before every prompt

The mode picker is the most quietly useful thing in the interface: it forces an explicit decision about how much machinery a task deserves, before the task starts.

Standard mode -- full coding agent with file editing, shell, file and web search, skills, planning, goals, subagents, workflows.
PTC mode -- all Standard capabilities, tools exposed through the Code Mode SDK so the model can combine multi-step operations in one TypeScript program.
Minimal mode -- two-tool coding agent with persistent bash and str_replace_editor.
Creator mode -- for building custom agent presets, with runtime inspection, plugin experiments and preset-authoring guidance.

07:25

Reliability: the label on the tin is accurate

Hangs, a session where the mouse was confined to a small square of the screen, compaction bugs where the agent lost the thread, context regressions in long sessions. He concedes he was hunting for breaking points. The product calls itself a developer preview and it behaves like one.

08:44

A bug caught on camera, and confirmed frame by frame

He clicks Creator mode and says it switches straight back. It does -- repeatedly.

Across twelve seconds the dropdown is opened at least five times and Creator mode is clicked each time. The menu dismisses, the composer chip still reads Standard mode, and the checkmark never leaves Standard. The selection silently fails.

The settings screen is the argument for the whole product

This is where "everything is a plugin" stops being a slogan. The model selector, the permission presets and the plan view are themselves plugins with off switches.

Settings: General, Models, Plugins, Agent presets. Plugin configuration exposes Shell, Agent loop, and Parallel tool calls: 10. A second list holds two dozen toggles, nearly all enabled: ui-model-selection, ui-permission-presets, ui-subagent, ui-trajectory, ui-plan, ui-skill, web-search-perplexity, hmr, and more.

Does it replace Claude? No -- and the reason is subscriptions, not quality

For deep work he still reaches for Claude Code. And if the model you want is Opus, a subscription buys far more of it than paying per token for the same model inside DSH. He is blunt about the framing error going around: this is a free harness, not a free Claude Code.

The Trajectory tab -- the feature worth stealing

Not a prettier log. A typed, filterable event stream over a three-lane timeline, with the actual tool arguments and the actual results, downloadable as a session log. The stated use is to read a bad run and then ask the harness to build the plugin that stops it recurring. It also shows something the chat view did not.

Lanes Input / Model / Tools; rows typed SYSTEM, USER, CONTEXT, ASSISTANT, TOOL. Tool rows carry raw JSON args: a glob returning TOOL_TIMEOUT in red, then greps with their literal regexes, a pwsh Get-ChildItem, a read with a full Windows path. One CONTEXT row reads "Current runtime context. This snapshot supersedes earlier runtime-context snapshots."
13:47

Same vague prompt, two spreadsheets

Build me an Excel sheet from my YouTube analytics. He chose the task because it forces skills, API calls and structuring scripts into one artifact, and he kept the prompt deliberately underspecified to see what each would do with the freedom.

DSH: YouTube Performance Report -- Trailing 3 Months. Six tabs. Multi-hue conditional formatting on views and engagement rate; top-10 and bottom-10 bar charts with no data labels at all.
Claude Code: YouTube Channel Report. Ten-plus tabs including README, Last 90 Days, All Videos, Top 50, Duration Buckets, Q2 Daily. The All Videos sheet runs fifteen columns across the full catalogue -- runtime in seconds, days live, views per day, like rate, comment rate, engagement rate, tags.
15:54

The same skill, run twice, disagreeing about who it was written for

Both harnesses run his own STORM research skill on the effects of sugar. Both follow the template correctly -- and he says so, which is the honest reading. What separates them is underneath: how much they verified, and, quietly, who they decided they were writing for.

Claude Code banner: 26 sources listed, 25 independently checked. Result: 8 confirmed clean, 13 corrected, 2 demoted, 2 figures untraceable to any primary source, 1 carried as an unverified lead. Audience line: a health-conscious decision-maker who also explains this evidence publicly.
DeepSeek banner: All 14 load-bearing citations independently checked. Result: 0 fabricated, 6 corrected, 3 demoted, with two citations flagged in place as industry-sponsored. Audience line: health-conscious general reader and public-facing content creator -- plus a reading-guide bullet of its own separating free and added sugars from the sugars in whole fruit.
17:11

The caveat he raises against his own result

Every skill he tested was authored for Claude Code. Skills get re-interpreted whenever the model or the harness changes, so a Claude-Code skill is a biased instrument for judging a different harness. A skill written natively for DSH, he expects, would score better and run faster. Then the closing instruction: stop taking his word for it and go test it on your own work.

What is worth carrying away

The harness is a bigger independent variable than anyone budgets for. Model pinned, wrapper swapped, and the same skill file produced two different audience definitions, two verification depths and two tones (16:20). If you compare agent outputs across sessions and only record the model, your comparison is not reproducible.

Instruction-as-file is what made the switch free. A rival vendor's harness read AGENTS.md, CLAUDE.md and CLAUDE.local.md and picked up an entire working setup with zero migration (05:02). Portability was bought years earlier by putting the context in files.

A summary view hides exactly the failures you need. The Trajectory tab showed a TOOL_TIMEOUT on the first call of the run being held up as the fast one (12:49). The chat view showed nothing, and neither did the narration.

Cost per token is the wrong unit; cost to completion is the right one. A cheap model running inefficiently inside a loop burns the discount (07:02). Headline million-in / million-out pricing is close to meaningless on its own.

Skills do not port cleanly, and they fail quietly when they do not. Both sugar reports looked correct. They specified different readers (17:11 and 16:20). A skill carries assumptions about the harness it was written against, and a wrong interpretation looks exactly like a right one.

Customization is only worth what your unmet pain is worth. The most useful thing he says about the product is that for research, knowledge work and document creation he has never once wished he could change the harness (09:28). Unlimited configurability is worth nothing to someone who has never hit the wall, and a great deal to someone who has.

Does this change how you work

Daily routine

Essentially no. You already run a settled harness, a large skill surface and enforcement hooks; installing a preview-grade competitor would cost a day and, on the source's own verdict, replace nothing. One habit is worth importing without the software: DSH makes you choose a mode before every prompt -- full context injection, or a stateless two-tool pass. You make that call implicitly today. Asking it out loud is free and harness-independent, and it matters most in the place you already delegate hardest, where a subagent's context is not yours.

[REDACTED: private track]

The most directly useful thing here is a failure, not a feature. The retrieval race fixes the headline variable (the model) and leaves a second one (reasoning effort) unequal, then attributes the whole delta to the intended cause -- the same shape as two spellings of one config reading as two configs. It is a clean, citable outside instance of the thing your own rules exist to catch, and it cost the source its best number. The Trajectory tab is a weaker second parallel: typed structured events that prose cannot smooth over, and a TOOL_TIMEOUT only the structured view surfaced. The harness itself is orthogonal to C++ cores under a pinned interpreter.

[REDACTED: private ML pipeline]

Moderate and indirect. Your Opus-plans / Sonnet-builds / Haiku-runs-bash arrangement is itself a harness composition, and the finding is that this layer moves the output with the model held still -- which argues for recording the orchestration config beside the model id whenever you compare generated artifacts across sessions. Cost-to-completion over cost-per-token also lands directly on a cascade that fans out to subagents. Nothing for the pipeline proper: leakage discipline, offset handling and checkpoint freshness are untouched by a harness swap, and adding a second unaudited harness beside a leakage guardrail buys nothing.

Skill authoring

The strongest transferable finding. You maintain a substantial skill surface plus hook-enforced behaviour. Section 7.3 says skills are harness-coupled and get silently re-interpreted on any harness or model change -- the observed divergence was two headers that both looked correct and named different readers. The cheap mitigation matches how you already write: make a skill state its own invariants explicitly enough that a drifted interpretation is detectable from the artifact.

Career track

Tangential but real. The harness-versus-model taxonomy is a well-formed answer to an interview question about agent architecture, and it comes with a numeric example and a named confound you can volunteer against yourself. The second half is worth more than the first.

polymarket_agent, claude-doc-reader, worldsim

No mechanism, no value. None of them is bounded by the harness layer, and there is nothing here to force a connection to.

Worth the eighteen minutes

Yes, with a discount applied to the numbers. The taxonomy is clean, the screen work is generous, and the author argues against his own result twice without being asked -- once on the skills being foreign to the harness under test, once on having deliberately hunted for breaking points. That is more self-correction than the genre usually offers.

What it is not is a measurement. Every latency figure is a wall-clock impression or a single observed race; there are no repeated trials, no medians, no variance, and the one race captured on camera had unequal reasoning effort on the two sides. Read the magnitudes as directional. The 0:52 frame is real; the "one minute versus five" is a memory.

The hole in the middle is deliberate and it is still a hole. He installed no plugins in order to judge the out-of-the-box feel -- which means the customization row of his own scorecard, the harness's entire reason to exist, is scored from a settings screen rather than from anything built. The one experiment that would most move the verdict is the one not run.

Who it is for. Anyone deciding whether an open harness is a cost saving (it is not) or a capability (it can be, if you have a specific unmet need). Anyone comparing agent outputs who has been recording only the model. Not for someone wanting a benchmark.

Follow-ups named in the video worth chasing: his own earlier video on putting a different model into Claude Code, tagged on screen at 11:22; the DeepSeek Harness developer docs, community plugin index, and the Cordis paper, all four linked from the product landing page at 01:55.
